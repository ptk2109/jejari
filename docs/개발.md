# 개발

빌드, 버전, 변경 기록, 브랜치, 시험 방법.

## 빌드

1. `brew install xcodegen`
2. 서명 Team을 `Configs/Signing.local.xcconfig`에 적는다 (커밋하지 않음): `DEVELOPMENT_TEAM = <Team ID>`
3. `xcodegen generate` (`project.yml` → `Jejari.xcodeproj`. 생성물이라 커밋하지 않음)
4. `xcodebuild -project Jejari.xcodeproj -scheme Jejari -configuration Debug -derivedDataPath build -allowProvisioningUpdates build`
5. `open build/Build/Products/Debug/Jejari.app`

- 새 파일을 추가하면 3번을 다시 한다
- 같은 Team으로 서명하면 다시 빌드해도 손쉬운 사용 권한이 유지된다. Team을 바꾸면 권한을 다시 켜야 한다

## 버전

유의적 버전(주.부.수)을 쓴다.

- 주: 저장 파일 형식이 호환되지 않게 바뀌거나 큰 변화. 1.0.0은 일반 사용자가 설치해 쓸 수 있는 첫 배포판
- 부: 기능 추가
- 수: 버그만 고침

버전은 `project.yml`의 `CFBundleShortVersionString`, git 태그 `v주.부.수`, `CHANGELOG.md`의 항목이 같아야 한다. `CFBundleVersion`은 배포할 때마다 1씩 올린다.

## 변경 기록

- 사용자가 알아챌 변경(기능 추가·변경·제거, 버그 수정)은 **그 변경과 같은 커밋에서** `CHANGELOG.md`의 `[Unreleased]`에 적는다
- 형식은 Keep a Changelog. 묶음은 추가 / 변경 / 수정 / 제거
- 사용자 입장에서 쓴다. 파일명·함수명 대신 무엇이 달라졌는지
- 내부 정리, 개발용 도구, 문서만 바뀐 것은 적지 않는다

## 브랜치

- `main`: 배포 기준. 직접 커밋하지 않는다
- 작업 브랜치에서 커밋하고, 버전을 낼 때 PR로 `main`에 합친다

## 버전 내기

1. `CHANGELOG.md`의 `[Unreleased]` 내용을 `[주.부.수] - 날짜` 항목으로 옮기고, 아래 비교 링크를 고친다
2. `project.yml`의 `CFBundleShortVersionString`, `CFBundleVersion`을 올린다
3. 커밋 → PR → `main`에 합치기
4. `main`에 태그 `v주.부.수`를 붙이고 푸시한다

배포판 만들기(서명된 zip, 자동 업데이트 목록, GitHub Release)는 배포 방식이 정해지면 이 절에 이어 적는다.

## 시험

개발 빌드는 `jejari://` URL 명령으로 시험할 수 있다. 결과는 `~/Library/Application Support/Jejari/last-result.json`.

| 명령 | 하는 일 |
|---|---|
| `save?name=` / `restore?name=&mode=full\|arrange` / `undo` | 저장, 불러오기, 되돌리기 (확인 창 없이) |
| `verify?name=` | 옮기지 않고 저장된 자리와 다른 창만 보고 |
| `collapse` / `wipe` | 한 화면으로 모으기 / 깨끗하게 비우기 (확인 창 없이) |
| `status`, `grant`, `open?window=` | 설정 점검 결과, 권한 요청, 창 열기 |
| `scramble` | 창 몇 개를 일부러 흐트러뜨림 (개발 빌드만) |
| `debugscan?app=`, `debugdrag`, `debugvd`, `debugremove`, `debugwindows` | 앱 창 분류, 끌어서 옮기기, 임시 모니터 경유, 가상화면 삭제, 자기 창 목록 (개발 빌드만) |

시험 순서의 예: `save` → `scramble` → `verify`(다름이 잡히는지) → `restore` → `verify`(전부 제자리인지).

불러오기 기록은 `~/Library/Application Support/Jejari/logs/<시각>-<배치>/`에 `before.json`, `report.json`, `after.json`으로 남는다. 결과가 이상하면 before와 after를 비교한다.

## macOS 업데이트 뒤 확인

비공개 API를 쓰므로 macOS를 올리면 다음을 확인한다.

- 설정 → 권한과 macOS 설정에서 "가상화면(Spaces) 기능"이 사용 가능인지
- `save` → `scramble` → `restore` → `verify`가 전부 제자리인지
- 모니터가 1대일 때 임시 가상 모니터를 거친 이동이 되는지
- Mission Control로 가상화면 추가·삭제가 되는지 (`debugremove`)
