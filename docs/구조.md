# 구조

제자리가 창을 모으고 되돌리는 방법과, 그렇게 정한 이유.

| `Permissions/` | `SettingsCheck` | 권한과 macOS 설정 점검 |

## 핵심 방법

### 창 찾기

- 표준 AX는 지금 보는 가상화면의 창만 준다. 다른 가상화면의 창은 원격 AX 요소(`_AXUIElementCreateWithRemoteToken`)로 앱마다 요소 번호를 훑어서 찾는다
- 훑기를 줄이려고 창 서버 목록(`CGWindowListCopyWindowInfo`, 권한 없이 모든 가상화면의 창 번호를 앱별로 준다)의 보통 창(레이어 0, 100×50 이상)을 다 찾으면 멈추고, 찾은 창의 요소 번호를 기억했다가 다음에 먼저 본다
- 뒤에서 막 켠 앱(미리보기 등)은 원격 요소로 창이 안 잡히기도 해서 표준 창 목록도 같이 본다
- 실행 중인 앱은 워크스페이스 목록(`NSWorkspace.runningApplications`)에서 찾는다. `NSRunningApplication.runningApplications(withBundleIdentifier:)`는 백그라운드에서 떠 있는 앱을 가끔 빠뜨린다
- 겹친 순서(앞뒤)는 화면에 보이는 창 목록의 순서를 먼저 쓰고, 나머지는 모든 창 목록의 순서로 붙인다. 모든 창 목록은 보이는 창의 앞뒤 순서를 늦게 반영한다
- Chrome 탭 주소는 AppleScript로 읽고 창 위치로 AX 창과 맞춘다. 다른 모니터의 창은 위치가 다르게 나오기도 해서, 안 맞으면 보고 있는 탭 주소가 같은 창으로 맞춘다
- 가상화면 정보가 없는 창은 닫힌 대화상자의 잔재로 보고 뺀다. 최소화·숨김 창은 가상화면 정보가 남아 있어 빠지지 않는다
- 전체화면 창은 `AXFullScreen`(가상화면 type 4)으로 구분해 저장만 하고 옮기지 않는다. 전체화면인 동안은 위치를 바꿀 수 없고, 전체화면 가상화면이 원래 화면 바로 뒤에 끼어들어 뒤 번호가 하나씩 밀린다
- AX 호출마다 0.5초 제한을 건다. 응답 없는 앱 하나가 전체를 붙잡지 않게

### 창 매칭

창 번호(CGWindowID)는 앱이 켜져 있는 동안만 같다. 그래서 배치 파일에는 넣지 않고, 불러올 때 짝지은 결과를 `matches.json`(`MatchCache`)에 배치마다 따로 기억한다.
다음에 불러오거나 다시 저장할 때 아직 맞는 짝은 창 번호로 먼저 확정한다(① 배치만으로 낮에 흐트러진 창을 되돌릴 때 등).

| | 내용 |
|---|---|
| 기억하는 것 | 저장 창 ↔ 창 번호, 그 창의 프로세스(pid, 커널의 시작 시각). 확실한 짝(창 번호, 40점 이상)만. 약한 짝은 틀렸을 때 굳어지므로 기억하지 않는다 |
| 쓰는 조건 (모두) | 그 pid의 프로세스가 같은 시각에 시작된 것(pid는 다시 쓰인다) / 그 프로세스가 배치의 창과 같은 앱 / 그 번호의 창이 지금 그 프로세스 것 |
| 안 쓰는 때 | 앱을 다시 켰거나 재부팅함, 그 창을 닫음, 배치를 다시 저장함(저장 시각이 다름) |
| 지우는 때 | 불러오기가 끝나 기억을 새로 쓸 때, 못 쓰게 된 짝과 지운 배치의 기억을 같이 지운다 |

직전 상태(되돌리기)는 곧 쓰는 것이라 창 번호와 프로세스를 파일에 같이 남기고, 쓸 때 같은 조건으로 확인한다.
`launchDate`는 macOS가 직접 띄운 앱(Finder)에서 비어 있어 커널의 시작 시각(`sysctl`)을 쓴다.

창 번호로 짝짓지 못한 창은, 제목도 자주 바뀌므로 단서를 점수로 합친다.

| 단서 | 점수 |
|---|---|
| 같은 문서 경로 (다른 파일이면 다른 창으로 확정) | 100 |
| 브라우저 탭: 같은 주소가 겹치는 정도 / 주소는 안 겹쳐도 사이트가 겹침 (사이트도 안 겹치면 다른 창). 불러올 때도 지금 창의 탭 목록을 읽어 비교하고, 못 읽었으면 보던 탭의 사이트로 | 100~140 / 80 |
| 같은 창 식별자(AXIdentifier). 같은 앱 창들 사이에서 그 식별자가 하나뿐일 때만 (모든 창이 같은 식별자인 앱이 있다) | 50 |
| 같은 제목 / 앞의 읽지 않은 수 "(3)"·수정 표시 "●"만 다름 / 제목의 바뀌지 않는 부분(프로젝트명 등) / 단어가 절반 이상 겹침 | 60 / 50 / 40 / 20 |
| 같은 크기 / 같은 위치 | 10 / 10 |
| 앱 안 순서 | 0~3 |

40점 이상은 바로 짝짓고, 약한 단서만 있으면 앱이 자리 잡은 뒤에 짝짓는다.

### 가상화면 옮기기

macOS는 창을 다른 가상화면으로 옮기는 공개 기능이 없고, 비공개 함수도 다른 앱 창에는 막혀 있다.

1. 데스크톱 N 단축키로 대상 모니터를 목표 가상화면으로 바꾼다 (번호는 모니터를 넘어 이어지는 전역 번호)
2. 창을 AX로 그 모니터로 옮긴다. 다른 모니터에서 오는 창은 그 모니터의 "지금 보이는" 가상화면에 들어간다
3. 같은 모니터 안에서 옮길 때는 다른 모니터를 잠깐 거친다. 모니터가 1대면 임시 가상 모니터(`CGVirtualDisplay`)를 만들어 거친다
4. 옮긴 뒤에는 정해진 시간만큼 기다리지 않고 위치·가상화면이 맞을 때까지(최대 0.5초) 확인한다. 반영되는 시간이 앱마다 다르다

임시 가상 모니터를 만들고 없앨 때 macOS가 내장 화면 해상도를 바꾸고 화면보다 큰 창을 줄인다. 그래서 배치 전에 만들고, 없앤 뒤 위치·크기를 다시 맞춘다.

### 가상화면 맞추기

- 필요한 것만: 지금 가상화면을 두고 바뀐 창만 옮긴다
- 초기화 후 다시 만들기: 모니터마다 1번만 남기고 지운다(지운 화면의 창은 보고 있는 화면과 상관없이 1번으로 모인다). 스냅샷 수만큼 다시 만들고 번호대로 옮긴다
- 자동: 스냅샷의 모니터가 없거나, 가상화면 uuid가 맞지 않으면서 수가 2개 이상 다르면 초기화
- 저장한 가상화면 uuid가 그 모니터에 모두 있으면 uuid로, 하나라도 빠졌으면 그 모니터 전체를 번호로 찾는다
- 모니터를 빼면 macOS가 그 모니터의 가상화면을 주 모니터로 옮긴다(1번은 주 모니터 1번에 합쳐짐). 필요한 것만 방식에서는 옮겨진 가상화면을 uuid로 찾아 쓴다
- 뺀 모니터를 다시 꽂으면 macOS가 옮겨 갔던 가상화면과 창을 원래 모니터로 되돌린다(1번 가상화면의 uuid도 되살린다). 그 사이 창이나 가상화면을 건드렸으면 되돌리지 않고, 되돌아온 가상화면의 순서는 뒤집혀 있을 수 있다. 가상화면 순서 자체를 바꾸는 방법은 없어 창만 번호대로 옮긴다
- Mission Control의 "+" 버튼과 삭제는 WindowManager 프로세스의 AX 트리에 있다. 삭제하려면 위쪽 막대를 펼쳐야 한다

### 불러오기 순서 (② 전체 복원)

1. 없는 모니터는 비슷한 모니터(같은 크기, 같은 모델명)로 대체하고 창 위치를 비율로 옮긴 뒤 쓸 수 있는 영역 안으로 맞춘다
2. 필요하면 가상화면을 초기화하고, 모자라면 만든다
3. 배치에 없는 앱을 처리한다 (그대로 / 숨기기 / 종료 요청). 포함된 앱이 숨겨져 있으면 다시 보이게 한다
4. 꺼진 앱을 실행한다. 파일을 보여 주던 창이 있으면 그 파일로 실행한다 (빈 채로 띄우면 파일 열기 창부터 뜨는 앱이 있어서). Chrome은 저장한 첫 창의 주소로 실행한다 (빈 채로 띄우면 프로필이 여러 개일 때 프로필 선택 창이 뜬다)
5. 앱별로 창을 훑어 뜬 창부터 짝짓고, 한 바퀴에 짝지은 창을 모니터·가상화면 순으로 옮긴다(전환을 줄이려고). 앱마다 창 생김·제목 바뀜 알림(AXObserver)을 받아 창이 뜨면 바로 다시 보고, 알림을 주지 않는 앱이 있어 2초마다도 본다. 파일을 보여 주던 창(Xcode 등)은 그 파일을, 창이 0개인 앱에는 다시 열기를, Chrome은 저장한 주소로 창을, JetBrains는 프로젝트를 하나씩 연다
6. 앱의 마지막 움직임(실행, 창을 열어 달라는 요청, 창이 생김, 창 수 변화) 뒤 30초 동안 조용하면 그 앱은 그만 기다린다. 제목 바뀜은 움직임으로 치지 않는다(시계가 도는 터미널처럼 계속 바뀌는 앱이 있다)
   - 입력을 기다리는 앱은 뒤로 미룬다. 모달 창이 있거나, 그 앱의 앞 창이 대화상자·크기 고정 창인데 저장한 창과 짝이 안 될 때다. 크기로는 가르지 않는다. 남은 것이 모두 그런 앱이면 끝내고 그 앱을 앞으로 띄운다. 최대 120초
   - JetBrains 프로젝트는 앱마다 하나씩 연다 (한꺼번에 보내면 하나만 열린 적이 있음). 다른 JetBrains 앱은 기다리지 않는다
7. 보관 화면으로 모으기와 남는 가상화면 정리
8. 겹친 순서를 맞추고(그 가상화면에서 이미 순서가 맞으면 건너뜀), 모니터마다 저장할 때 보던 가상화면으로 돌아간다
9. 앱은 떠 있는데 짝을 못 찾은 창은 끝난 뒤 3분 동안 지켜본다(아래 "늦게 뜨는 창")

### 늦게 뜨는 창

로그인을 거치는 메신저처럼 불러오기가 끝난 뒤에 창이 뜨는 앱이 있다. 기다리는 시간을 늘리는 대신 끝난 뒤에도 지켜본다.

- 지켜보는 동안 메뉴 맨 위에 "늦게 뜰 창 N개 기다리는 중 · 끝나는 시각"이 보이고, 하위 메뉴에 창 목록과 "그만 기다리기"가 있다. 메뉴는 열린 동안 바뀌지 않아 남은 시간 대신 끝나는 시각을 쓴다
- 창이 뜨면 가상화면을 바꾸지 않고 옮길 수 있을 때(이미 목표 가상화면에 있거나, 목표가 그 모니터에서 지금 보이는 가상화면이고 창도 지금 보이는 화면에 있을 때)만 바로 옮긴다. 키보드·마우스 입력을 흉내 내지 않으므로 사용자는 그동안 마음대로 쓴다
- 가상화면을 바꿔야 하면 단축키 입력이 사용자 입력과 섞일 수 있어 옮기지 않고 알린다. 알림, 메뉴, 결과 창에서 누르면 옮기고 원래 보던 가상화면으로 돌아간다
- 다른 저장·불러오기·정리하기를 시작하면 지켜보기를 멈춘다

## 정한 것

- 저장 기준은 Dock에 아이콘이 있는 일반 앱 전부. 창이 없어도 실행 중이면 기록한다
- 시스템 설정 창은 저장할 때 체크를 꺼 둔다. 잠깐 열어 두는 창이고 다시 열면 다른 화면으로 열려 짝이 지어지지 않는다
- 뺀 창은 지우지 않고 표시만 해서 나중에 다시 포함할 수 있게 한다
- 같은 이름으로 다시 저장하면 불러올 때 설정과 뺀 앱·창을 이어받는다. 뺀 창은 새로 찍은 창과 창 번호(기억한 짝이 아직 맞을 때) 또는 강한 단서(40점 이상)로 짝지어진 것만 이어받는다
- 배치 파일에는 앱이 켜져 있는 동안만 맞는 값(창 번호, pid)을 넣지 않는다. 오래 두는 파일이라 재부팅 뒤 다른 창을 가리킬 수 있다
- 저장 창은 덮어쓸 배치를 목록에서 고른다(처음엔 마지막으로 불러온 배치). 새 이름이 기존 이름과 같으면 저장하지 않는다. 이름을 잘못 쳐서 덮어쓰지 않게
- `jejari://`는 웹페이지나 다른 앱도 보낼 수 있다. 배포판은 읽기·창 열기만 항상 받고, 저장·불러오기·되돌리기·정리하기는 설정에서 허용했을 때만, 가상화면을 지우거나 앱을 끄는 것은 허용했어도 매번 확인한다. 개발 빌드는 시험용으로 모두 확인 없이 받는다
- Hardened Runtime을 켠다. 손쉬운 사용 권한을 가진 앱이라 코드 주입을 막기 위해서다. 필요한 예외는 Apple Events(Chrome 탭 주소 읽기) 하나뿐이고 `Jejari/Jejari.entitlements`에 둔다. 배포판에는 개발 인증서 서명 때 Xcode가 넣는 디버거 연결 허용(`get-task-allow`)을 넣지 않는다. 비공개 API, 임시 가상 모니터, Sparkle 업데이트는 켠 상태에서 확인했다
- 앱을 강제로 끄지 않는다. 종료는 정상 종료 요청이고, 메뉴에서 할 때는 목록을 보여 주고 확인한다
- 불러오기 직전 상태를 저장해 되돌리기를 할 수 있게 한다
- 불러오기가 끝난 뒤에는 사용자가 누르지 않는 한 가상화면을 바꾸지 않는다. 사용자가 작업 중일 수 있다
- 불러오기 기록(`RunLogStore`)은 배포판 기본 끔, 개발 빌드 기본 켬. 창 제목·문서 경로·탭 주소가 들어가고 배포판 사용자의 기록은 개발자가 볼 수 없어서다. 문제를 알려 줄 때 켜서 폴더를 보낸다. 자세한 진단 기록을 더할 때도 이 설정이 켜졌을 때만 남긴다
- 비공개 API는 OS에 없으면 그 기능만 끄고 위치·크기 복원은 계속한다
- 업데이트는 Sparkle로 한다. 최신 GitHub Release의 `appcast.xml`을 하루에 한 번 확인하고, 업데이트 파일은 EdDSA 서명으로 검증한다. 개발 빌드는 배포판과 번들 ID가 같아 확인하지 않는다
